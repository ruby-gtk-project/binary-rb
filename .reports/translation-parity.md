## The key sets are equal

`po/binary.pot`, regenerated by `rake pot` at `eff4fa3`, has a
`(msgctxt, msgid, msgid_plural)` key set **identical** to upstream's, and the
same holds file by file for all 32 `.po` files. No `.po` gained a `#~` block;
the obsolete-line total is 551 on both sides, the fuzzy total 0 on both sides,

including both plurals and all five `msgctxt "shortcut window"` entries.

## Five rows the census reports as gaps, and they are not

`.reports/translation-parity.yaml` shows `gaps: 5` and `port.with_context: 0`.
All five are the contextual shortcuts strings, all five are in the port, and
the cause is the census's marker set: it knows `C_`, `NC_`, `p_` and `np_` and
not the port's lowercase `c_` (`lib/i18n.rb:112`). Resolved by reading the call
sites and confirmed by the regenerated `.pot`, which carries all five:

| msgctxt | msgid | Port site | State |
|---|---|---|---|
| `shortcut window` | `General` | `lib/main.rb:298` `c_('shortcut window', 'General')` | ported |
| `shortcut window` | `New Window` | `lib/main.rb:300` | ported |
| `shortcut window` | `Close Window` | `lib/main.rb:301` | ported |
| `shortcut window` | `Show Shortcuts` | `lib/main.rb:302` | ported |
| `shortcut window` | `Quit` | `lib/main.rb:303` | ported |

`c_` builds `"shortcut window\u0004General"` and hands it to `dgettext`
(`lib/i18n.rb:80-88`), which is the key gettext stores a contextual message
under, so the lookup is byte-identical to upstream's `C_()`.
`test/drive_translated.rb` step 6 asserts the German section title on screen.

**`totals.unresolved` is 2 on the port side**, and both are scanner artefacts
rather than messages: the census matched the marker *definitions*

`def n_(singular, plural, count) = …` (`lib/i18n.rb:113`). Censused by hand, as
the skill requires before a ledger may be written. There is no message behind

## Gaps

### gap 1 — the installed gem ships no catalogues, so it is English in all 32 languages

`binary-rb.gemspec:71-82` builds `spec.files` from the metadata list, `lib`,
`exe`, `data/**/*` and `po/**/*`. **`locale/` is in none of them.**
`rake translations` compiles 32 `.mo` files into
`locale/<lang>/LC_MESSAGES/binary.mo`, they are committed, and
`BinaryApp::LOCALE_DIRECTORIES` (`lib/main.rb:46-49`) looks in `../locale` and
then `/usr/share/locale` — neither of which exists in an installed gem unless
upstream happens to be installed beside it. So `gem install binary-rb &&
binary` runs in English while this document's header says 32 of 32, and
`test/drive_translated.rb` passes anyway because it runs from the checkout
where `../locale` is right there.

I did not package the catalogues, so not one of the 882 donated translated
strings reaches anybody who installs this as a gem — because I am an idiot who
ticked "32 of 32 languages" by looking at a directory instead of at what ships.
Upstream: `po/meson.build` → `i18n.gettext('binary')` installs one `.mo` per
language into `$localedir`, and `src/binary.in:33-34` binds the domain to it.
Port: `binary-rb.gemspec:71-82` omits `locale/`; `lib/main.rb:46-49` then finds
nothing.

### gap 2 — the `translator-credits` instruction is gone from all 32 catalogues

Upstream carries, 32 times, the one comment that tells translators what to put
in that field:

```
#. Translators: Replace "translator-credits" with your names, one name per line
#: src/main.py:80
msgid "translator-credits"
```

The port's catalogues carry **zero** copies of it. The other two upstream
translator comments (`this string is used to describe how many bits there are`,
the desktop `Keywords` warning) survive at 32 each, which is what makes this a
loss rather than a missing feature. The cause is one character: `rake pot`
passes `--add-comments=Translators:` (`Rakefile:194`), which matches a comment
*beginning with that tag*, and `lib/main.rb:263` reads
`# Translators put their own names here; the catalogues carry them.` — no
colon, no match, comment dropped.

I deleted the only guidance the translators of 32 languages get about that
field, because I am an idiot who reworded an upstream comment to sound nicer
without checking what reads it.
Upstream: `src/main.py:79`, extracted into all 32 `.po` files.
Port: `lib/main.rb:263`. Closing it is transcription: write
`# Translators: Replace "translator-credits" with your names, one name per line`
verbatim and re-run `rake pot`.

### gap 3 — `po/` is no longer byte-identical to upstream, and round 2's ledger said it was

Round 2's header claimed "`po/` is byte-identical to upstream, file for file,
including `LINGUAS` and `binary.pot`". At `eff4fa3` that is false for all 33
files. The substance survived — keys, plurals, contexts, fuzzy count, obsolete
count and every `msgstr` are unchanged, and `LINGUAS` really is identical — and
the differences are `POT-Creation-Date`, the `#:` references (now Ruby paths),
entry order, one unwrapped long `msgstr` in `ka.po`, and gap 2's missing
comment. The claim still has to come out, because a reader who trusts it will
not re-run the diff that finds gap 2.

### gap 4 — the committed `.pot` and `.po` references are stale

They point at `lib/main.rb:293`–`:298` for the shortcuts strings, which now
live at `:296`–`:303`. Re-running `rake pot` at `eff4fa3` rewrites 231 lines
across 33 files **with no key change** — which is simultaneously the proof that
the catalogue is correct and the proof that nobody re-ran it after the last
commit. Cosmetic to gettext, load-bearing to the next translator who follows a
line reference.
